==============================================================================
INTRODUCTION                                                      *manuscript*

manuscript.nvim takes a manuscript written in LaTeX, Rnoweb (knitr's .Rnw),
R Markdown (.Rmd) or jnoweb (Knit.jl's .jnw: LaTeX with Julia chunks), in
one file or several, from its first line to its publication. All four work
the same way, with the same commands:

  |:Manuscript| new         a new manuscript, from a template
  |:Manuscript| build       while you write: the PDF of the part you are in,
                            or of the whole, or of a variant of it (anon,
                            review, a journal's), in the background
  |:Manuscript| export      Word files for your collaborators, one per part
  |:Manuscript| merge       their edits back into your sources, in a diff
  |:Manuscript| submit      what a journal asks for: the PDFs, and a zip of
                            the LaTeX that compiles them, anonymous or not
  |:Manuscript| diff        a PDF with the changes since what you sent or
                            submitted, as tracked changes
  |:Manuscript| respond     the response to the reviewers, a point for each
                            of their comments
  |:Manuscript| archive     the code and data of its repository, zipped

It defines one command, |:Manuscript|, and no keymaps (see
|manuscript-keymaps|). Nothing is written in your manuscript's folder but
the PDFs you build, and .build/, export/, submission/ and diff/, which keep
themselves out of git.

                                                         *manuscript-progress*
Builds, exports and diffs run in the background, each with one message
updated in place: its step (knitting, and which chunk; LaTeX...), the time
since it began, how far it is (from its steps, or estimated from how long
the same build took before), and at the end, done or failed. In Nvim 0.12+
these are |progress-message|s: shown by the |ui2| message window, a plugin
such as fidget, the terminal (as a progress bar, if it supports it), or the
'statusline' with |vim.ui.progress_status()|; when done, also in |:messages|.
Before 0.12, a notification per step.

Requires Nvim 0.10+, neoffice.nvim (it reads Word files) and pandoc. For .Rnw
and .Rmd files: R with knitrmini (or knitr, or rmarkdown: see
|manuscript-knit|); for .jnw files: Julia with Knit.jl. For builds and
|manuscript-diff|: latexmk (and latexdiff).

==============================================================================
THE MANUSCRIPT                                            *manuscript-project*

Its root is the file that is compiled: a .tex, .Rnw or .jnw with
`\begin{document}`, or an .Rmd with a YAML header (`---` on its first line).
From any file of the manuscript it is found: the one a `% !TeX root = ...`
line names, the file itself if it is a root, the root in its folder (or a
folder up to three above) that includes it, or the one root in its folder (an
.Rnw, .Rmd or .jnw before a .tex: a .tex beside one is its knitted output).

Its parts, each built alone into its own PDF and exported into its own Word
file:
  .Rnw     its child chunks, in order, named after their files without a
  .jnw     leading number: `<<child='2_main.Rnw'>>=` is the part "main"
  .Rmd     its child chunks: ```` ```{r child="1-main-text.Rmd"} ```` is
           "main-text"
  .tex     its `\include{}`s ("appendix1"), and the root itself, as "main",
           if its body has text of its own besides them
  else     the root alone.

Its files are the root, the parts and every `\input{}` and `\include{}` in
them (recursively): what the merge edits, what a diff compares. An
`\input{intro}` is text of whatever includes it, not a part of its own.

The .bib files are those of its `\addbibresource{}` and `\bibliography{}`, and
of an .Rmd's YAML `bibliography:` (a file or a list; relative or absolute),
or else those in its folder.

==============================================================================
BUILD                                                       *manuscript-build*

:Manuscript build [{part}|all] [{variant}] [{name}.pdf] makes the PDF as you
would by hand (knit, then LaTeX), in the background: you go on writing, and
it says when it's ready.

  :Manuscript build            the part of the file you are in (main.pdf from
                               2_main.Rnw), or the whole if you are in the
                               root (1_index.pdf)
  :Manuscript build appendix1  that part
  :Manuscript build all        the whole manuscript
  :Manuscript build anon       the part you are in, anonymous: main-anon.pdf
                               (|manuscript-variants|)
  :Manuscript build main main_v2.pdf
                               that part, as main_v2.pdf (main.pdf stays as
                               it was)

Only the PDF is written beside the root: the knitted .tex and LaTeX's files
are in .build/<part>/ (.build/ keeps itself out of git), where the next build
finds them, so that it only reruns what it must. With a {name}.pdf, the
build is made under that name; the usual PDF is left as it was. A name only
(no folder), and not another part's.

A part is knitted from a copy of the root with only its child chunk
evaluated: no more setting `eval=FALSE` by hand, nor naming the output. A
part of a .tex root is a copy of it with the other parts left out.

                                                             *manuscript-knit*
What knits each kind (the option `knit` chooses another):
  .Rnw     knitrmini if installed, else knitr
  .Rmd     knitrmini (a version that knits .Rmd files: else rmarkdown), the
           same way as an .Rnw: chunks as LaTeX, the prose through pandoc
           (no template), the document from its YAML
           header's `documentclass`, `classoption`, `preamble` (files
           `\input` before `\begin{document}`), `header-includes`,
           `bibliography`, `biblatex`, `title`, `author`, `date` and
           `abstract`. With an `output:` in its YAML header (a bookdown
           format, a template...), or `knit = "rmarkdown"`: rendered with
           rmarkdown in that format, into a .tex that latexmk builds.
  .jnw     Knit.jl, in a Julia worker: one hidden Julia per manuscript's
           folder, started at its first build and kept until Nvim exits, so
           Julia and the packages a document loads start once (the first
           build takes seconds; the next, under one). Its command is the
           option `julia`, run with `--project=@.` (the document's
           environment, else your default one, where Knit.jl must be).
  .tex     latexmk.

A text edit rebuilds in a LaTeX pass and a second of knitting. A build of
the whole keeps the labels of all the parts (.build/<root>-labels.aux), with
which a part's references to the others get their numbers; a part built
before any build of the whole makes one first. An export reuses it too, when
it's newer than the sources.

The PDF opens the first time (with |vim.ui.open()|); viewers such as zathura
or sioyek reload it by themselves after that. LaTeX's errors go to the
|quickfix| list, at their line in your sources when it can be found there
(else in the .tex), and leave it when a build succeeds. A build asked for
while another runs follows it (two at once would write the same files).

:Manuscript build watch builds when a file of a manuscript (.Rnw, .tex, .bib)
is written; again, it stops (`build_on_save = true` from the start).

:Manuscript clean removes .build/ (every build's files, and the labels of
the whole); :Manuscript clean {part} (or {name}: a variant's build,
main-anon, or one under a name), those of that build only. The PDFs stay.
(After a clean, the next build of a part builds the whole first.) Files that
builds left beside the root before .build/ existed go too.

                                                        *manuscript-figures*
Standalone LaTeX figures (a TikZ figure in `figures_manuscript/fig1.tex`, a
document of its own that makes `fig1.pdf`) are built before the manuscript's
LaTeX (build, export, diff), when they changed: their .tex, or a file they
read (the panels R made: in their .fls), is newer than their PDF. They are
found by themselves: each `\includegraphics{X}` (in an .Rmd, also `![](X)`
and `knitr::include_graphics("X")`) whose PDF has a .tex beside it. Their
engine: their `% !TeX program = xelatex` line; else the one that built them
last (a figure made by hand, or by a Makefile, stays as it was made); else
pdfLaTeX, or LuaLaTeX if they load fontspec. Their LaTeX errors go to the
quickfix list (and the figure is built again next time); :Manuscript clean
removes their auxiliary files too. The option `figures`: >lua

  figures = true,                          -- (the default) as above
  figures = false,                         -- never
  figures = { "../figures/2_final/*.tex" } -- also these (globs, relative to
                                           -- the manuscript's folder)
<
:Manuscript build in a figure's .tex builds just it: it is a manuscript of
one file.

==============================================================================
EXPORT                                                     *manuscript-export*

:Manuscript export makes a Word file of each part in a new folder of the
manuscript's: `export/<date>/` (`<date>-2`, ... for another one that day).
Each file is named after its part and the folder, `main_2026-11-25.docx`, so
the versions you send don't overwrite each other at your collaborators'.
For an .Rnw root, each part is knitted as you would by hand: a copy of the
root with only that part's child chunk evaluated (your root isn't changed).
First the whole manuscript is built, as `:Manuscript build all` does (so
its PDF is brought up to date too), so that each part's references to the
others (`\ref{fig:s1}` in the main text) get their numbers; not if your last
build of the whole is newer than the sources.

Then each part is converted as `toword` did: the LaTeX made readable by
pandoc (siunitx, authblk, knitr's environments, appendices, ...), pandoc with
citeproc, a citation style, a reference .docx for the styles, and filters for
cross-references, appendices, titles, figures (PDF figures become PNG
images) and tables; the author block aligned. The files made on the way stay
in Nvim's cache. The Word files don't carry paths of your folders.

Each export is a snapshot of what you sent: its folder also keeps, in
`.manuscript/`, the LaTeX its Word files were made from and the git commit
(and a copy of the sources if they had changes not committed). |:Manuscript|
merge and diff use it.

MERGE                                                       *manuscript-merge*

In a Word or LibreOffice document (opened with neoffice.nvim), from any
folder: >vim

  :Manuscript merge                  " the manuscript found by itself
  :Manuscript merge ~/papers/vipers/ " or this one (a file of it, its folder)
<
The manuscript is the one given, or else the one this document is from: of
the current folder's and those you exported or merged into, the one that has
most of its text, clearly; else it asks (with completion).

Nothing is written. Each source file the document changes opens in a new tab,
in a |diff| view: on the left what it would be with the document's edits,
and your file on the right (as in vim-fugitive). In your file, take the ones
you want with |do| (|]c| goes to the next one) and write it. The |quickfix|
list has every edit ("change: old → new", "add:", "delete:"), the unresolved
comments, and anything that needs your eyes, at their line in the source;
its title says how many. It follows your file: an edit you take (or make
yourself) leaves it a moment later. Its items open where their file is shown
already (<CR>, |:cnext|...), so the diff stays as it is; those about
paragraphs only the document has (the title page...) come last, and open the
document in its tab. (While a merge tab is open, 'switchbuf' is
"useopen,usetab,newtab"; yours again when it is closed.)

The edits are written in the source's own language: LaTeX in a .tex or .Rnw
(`\emph{}`, `\parencite{key}`), Markdown in an .Rmd (`*...*`, `**...**`,
`[@key]`), with raw LaTeX in it left as it is. Every file of the manuscript
is a source: a paragraph in an `\input{}` file is edited there.

Running it again is safe, and it reads your sources as they are in Nvim,
with what you took and haven't written yet: what your source has already is
left alone, and its tab shows only the rest. So you can fix the .bib, say,
and run it again in the middle of a review.

What the document was ~
                                                       *manuscript-merge-sent*
To tell the edits from what the export writes (citations, computed values,
references...), the merge compares the document with the export it was made
from: of the exports of |manuscript-export|, the one most like it. Without
one (exported by other means), a .docx with no tracked changes in the
sources' folder or below, like this document and the most like your sources,
or a copy named `*.sent.docx` beside the document; or give it: >vim

  :Manuscript merge ~/papers/vipers/ old/main.docx
<
With it, every edit of every round is found: tracked or not, accepted,
rejected, yours or theirs, whole paragraphs added or deleted. Without it,
the document's text as sent is its text with all tracked changes rejected,
so only the edits still tracked are found (and it says so).

If you change the sources and export again during a review, the new export
no longer is what the document was made from: merge the review first.

How it works ~
Each paragraph of the document is paired with the paragraph of the sources
with the most words in common (a short one, like a heading, only in the file
of the paragraphs around it). Where the document and the export differ, the
source changes, written as LaTeX: italics as `\emph{}`, bold as `\textbf{}`,
special characters escaped. Your line wrapping, `%` comments and everything
around the edits stay as they are.

- A citation from which a reference was removed is rebuilt with the keys that
  are left (`\parencite{a,b}` → `\parencite{a}`).
- A citation typed in the document, like "(Smith & Lee, 2020; Kim et al.,
  2021)", is looked up in the .bib files by first author, year and number of
  authors. One it can't find, or can't tell apart, stays as text, and its
  item in the quickfix list goes to it in the proposal: replace it there with
  your citation picker (citeref.nvim, for example), then take it with |do|.
  A reference missing from your library: add it (zotero.nvim, with Better
  BibTeX keeping the .bib up to date) and merge again.
- A computed value (`\Sexpr{}`), a reference, a unit or a formula edited in
  the document is kept as it is, and listed. Deleted with the text around it,
  it goes with it.
- Unresolved comments are listed at their line in the source (resolved ones
  were dealt with during the review).
- If your source changed since the export, where the document changed it
  too, your text is kept and the place is listed as a conflict.
- A paragraph the document added goes after the one before it; one it deleted
  is deleted; both are listed. Paragraphs not found in the sources (tables or
  text written by R, the title page, the reference list) are listed when they
  changed.

DIFF                                                         *manuscript-diff*

:Manuscript diff [{part}] [{variant}] [{old}] [{new}] [{oldkey}={newkey} ...]
makes a PDF with the changes between two versions of the manuscript, marked
as tracked changes (latexdiff), in `diff/<old>-vs-<new>.pdf`, and opens it
(the first time: then your PDF viewer reloads it). Its LaTeX files are kept
in .build/diff/, so making the same diff again runs LaTeX only as much as
needed. With a variant, it is built with its switches (an anonymous diff for
a double-blind resubmission). A version is:

  (none), @              the last export or submission: what you sent
  @2, @2026-10-23, @geb  an export or a submission, by its place (@1 is the
                         last; see :Manuscript versions) or its folder's
                         name (@geb: the last submission to geb)
  HEAD, c2ffc81, v1      a git revision: the manuscript's files as they were
                         then, knitted with today's data and code
  path                   a .tex file (as it is), or an .Rnw/.tex root or its
                         folder (knitted)
  .                      the manuscript now (the default {new})

With a part's name (main, appendix1...), only that part is compared:
`:Manuscript diff main` gives `diff/main-<export>-vs-now.pdf`, the changes to
the main text since what you sent; `:Manuscript diff appendix1 HEAD~2` those
to the appendix since a revision. An export kept each part's LaTeX; the
manuscript now and a git revision are knitted with only that part (as a
build: without a build of the whole yet, one is made first, for the numbers
of its references to the others). A git branch with a part's name is
`heads/<name>` here.

<Tab> completes the parts, variants, exports, submissions, tags, branches
and recent commits. A citation key renamed since (the same DOI, or title
and year, in the old and new .bib) is renamed in the old version, so that it
doesn't show as a change; `oldkey=newkey` arguments add to them. The PDF is
built with lua-ul when it is installed (ulem stops hyphenation), and some
room to stretch lines.

VARIANTS                                                 *manuscript-variants*

A variant is a version of the same sources: a name for LaTeX switches that
its builds turn on. Every build defines every switch (`\ifanonymous`,
`\iflinenumbers`...), off but for its variant's, and `\manuscriptvariant`
(its name), before your sources are read; your preamble uses them:
>latex
  \ifanonymous\else
    \author{Ana Author} \affil{University}
  \fi
  \iflinenumbers\usepackage{lineno}\linenumbers\fi
<
Built otherwise (by hand), the switches are undefined: a guard in the
preamble defines them, off (the templates have it, see |manuscript-new|):
>latex
  \ifcsname ifanonymous\endcsname\else\expandafter\newif\csname ifanonymous\endcsname\fi
<
(Not `\ifdefined\ifanonymous`: TeX would count a skipped `\ifanonymous` as
a conditional, and its `\fi` would close the wrong one.)

The variants are:

  anon         anonymous = true; the PDF has no author nor file paths in its
               metadata either
  review       linenumbers = true, doublespacing = true
  draft        draftversion = true, linenumbers = true

and a manuscript's own, in its .manuscript.lua (they may redefine these):
>lua
  return {
    variants = {
      geb = { anonymous = true, linenumbers = true, doublespacing = true,
              submit = { appendix_name = "Appendix_S%d" } },
    },
  }
<
A switch is a word of letters; the switches the templates use are
anonymous, draftversion, linenumbers, doublespacing and figuresatend.
`:Manuscript build geb` makes <part>-geb.pdf; |:Manuscript| diff and submit
take a variant too.

==============================================================================
SUBMIT                                                     *manuscript-submit*

:Manuscript submit [{variant}] [anonymous|named] makes what a journal asks
for, in a new folder submission/<variant>-<date>/:

  main.pdf                the main text (the part "main", or the first),
                          built with the variant's switches
  Appendix_S1.pdf, ...    each other part, its own PDF
  title_page.pdf, ...     title_page.tex, cover_letter.tex and response.tex
                          beside the root, if there, built (named: they
                          have the authors)
  latex/                  what compiles main.pdf, and nothing else:
    main.tex                knitted, its `\input{}`s inlined, its comments
                            out, the switches resolved in the text: an
                            anonymous source has no authors at all, not even
                            in a branch TeX would skip
    figures/                the pictures it reads (those a macro makes too:
                            `\includegraphics{panels/p_#1}`), paths rewritten
    references.bib          only the entries it cites (and their crossref),
                            from all its .bib files; and main.bbl
    *.sty, *.cls            the local packages and classes it reads (yours
                            in TEXMFHOME too: a journal doesn't have them)
  <folder>-latex.zip      latex/, to upload

Before it is kept, latex/ is compiled on its own, in another folder and
without your TEXMFHOME: if it doesn't build there, the submission fails
here, not at the journal. `anonymous` or `named` force the variant's
anonymity (`:Manuscript submit geb named`, once accepted).

An anonymous submission is searched for who wrote it: the names and emails
of the author block of the named version (`\author`, `\affil`, `\thanks`...;
an .Rmd's YAML authors), git's user, and the option `identity`. Where they
are (in the source, in a PDF's text or metadata; a file path of your
computer in a PDF) goes to the |quickfix| list; those in the bibliography,
self-citations, after the others, as such (they are no leak). A citation
key, though it names an author, isn't searched.

A variant's `submit` table changes how: >lua

  submit = {
    name = "main",                 -- main.tex, main.bbl, main.pdf
    appendices = "separate",       -- or "inline": one document
    appendix_name = "Appendix_S%d",
    figures = "names",             -- or "numbered": fig1.pdf, fig2.png...
    flat = false,                  -- true: figures beside main.tex, no
                                   -- folder (Elsevier's Editorial Manager)
    comments = false,              -- true: they stay in the source
    extras = { "title_page", "cover_letter", "response" },
  }
<
A submission is recorded as an export is (the LaTeX it was made from, the
commit): `:Manuscript diff @geb` makes the tracked changes since it. A
resubmission (another one with the same variant) has them in it too:
changes_since_<the last one>.pdf, built with the variant's switches
(anonymous, for a double-blind journal). `changes = false` in the variant's
`submit` table: not.

==============================================================================
RESPOND                                                   *manuscript-respond*

:Manuscript respond opens response.tex beside the root, or, the first time,
a buffer for the reviewers' comments: paste them as the journal sent them
(the whole decision letter will do), and |:w| writes response.tex, with a
point for each comment, quoted, and room for your answer after it. A
reviewer starts at a line that names one ("Reviewer #2:", "Comments of
Referee 1", "Associate Editor"); a point at a line numbered as reviewers do
(1., 2), (3), Comment 4, R1.5, a bullet), or, when none is, at each
paragraph. In it, `\changed{label}` says where a change is: its page in the
revised manuscript (from its last build of the whole, .build/<root>/; xr).
|:Manuscript| submit builds it into response.pdf.

==============================================================================
ARCHIVE                                                   *manuscript-archive*

:Manuscript archive puts the code and data of the manuscript's repository in
one zip, for Zenodo or Dryad: submission/<repository>-<date>.zip. Its files
are those git tracks, as they are now (it says so when some changed since
the last commit), with those of `archive.include` (results kept out of git)
and without those of `archive.exclude`: globs relative to the repository,
in .manuscript.lua: >lua

  return { archive = { include = { "results/*.rds" }, exclude = { "raw_data/iucn" } } }
<

==============================================================================
NEW                                                           *manuscript-new*

:Manuscript new [{template}] [{folder}] makes a new manuscript in {folder}
(new or empty; `manuscript` by default) from a template, and opens its
root. The plugin's templates, one per kind (rnw, rmd, tex, jnw), are a paper
of a main text and an appendix (its own title block, references and
numbering), with the switches of |manuscript-variants| in the preamble
(the title and authors in 01_metadata.tex, the authors in `\ifanonymous`;
line numbers, double spacing, figures at the end), a title page and a cover
letter for |manuscript-submit| (documents of their own: no number), an empty
references.bib and a .manuscript.lua for its variants. Your own: the folders
of the option `templates` (they win by name). <Tab> completes them.

==============================================================================
COMMANDS                                                         *:Manuscript*

:Manuscript new [{template}] [{folder}]
                                A new manuscript (|manuscript-new|).
:Manuscript build [{part}|all|watch] [{variant}] [{name}.pdf]
                                The PDF of the current part, a part, or the
                                whole; watch: on each write
                                (|manuscript-build|).
:Manuscript clean [{part}|{name}]
                                What the builds left (all, or a build's).
:Manuscript export              Word files of the manuscript in export/<date>/
                                (|manuscript-export|).
:Manuscript merge [{manuscript}] [{export}]
                                In a document: its edits into the sources, in
                                a diff view (|manuscript-merge|).
:Manuscript diff [{part}] [{variant}] [{old}] [{new}] [{oldkey}={newkey} ...]
                                A PDF with the changes between two versions,
                                of the whole or of a part (|manuscript-diff|).
:Manuscript submit [{variant}] [anonymous|named]
                                The files for a journal (|manuscript-submit|).
:Manuscript respond             The response to the reviewers
                                (|manuscript-respond|).
:Manuscript archive             The repository's code and data, zipped
                                (|manuscript-archive|).
:Manuscript versions            The exports and submissions, for
                                :Manuscript diff @N.

Alone, it lets you pick one.

KEYMAPS                                                   *manuscript-keymaps*

manuscript.nvim sets no keymaps. For example: >lua

  vim.keymap.set("n", "<leader>rr", "<Cmd>Manuscript build<CR>", { desc = "Build this part" })
  vim.keymap.set("n", "<leader>rR", "<Cmd>Manuscript build all<CR>", { desc = "Build the whole" })
  vim.keymap.set("n", "<leader>rc", "<Cmd>Manuscript clean<CR>", { desc = "Clean the build" })
  vim.keymap.set("n", "<leader>me", "<Cmd>Manuscript export<CR>", { desc = "Export to Word" })
  vim.keymap.set("n", "<leader>md", "<Cmd>Manuscript diff<CR>", { desc = "Changes since the last export" })
  -- or on the command line, for a variant, a part, a version (<Tab> completes them)
  vim.keymap.set("n", "<leader>rs", ":Manuscript submit ", { desc = "Submit (a variant)" })
  -- in documents (neoffice's filetype), next to its <leader>w keymaps
  vim.api.nvim_create_autocmd("FileType", {
    pattern = "neoffice",
    callback = function(ev)
      vim.keymap.set("n", "<leader>wm", "<Cmd>Manuscript merge<CR>", { buffer = ev.buf, desc = "Merge into the sources" })
    end,
  })
<
==============================================================================
OPTIONS                                                   *manuscript-options*

No setup() is needed. These are the defaults: >lua

  require("manuscript").setup({
    export_dir = "export",   -- where exports go, in the manuscript's folder
    csl = nil,               -- the citation style: a .csl in the manuscript's
                             -- folder, or the bundled one
    reference_docx = nil,    -- the Word file whose styles exports use
    move_figures = false,    -- figures at the end of each Word file
    move_tables = false,     -- tables at the end
    dpi = 200,               -- PDF figures become PNG at this resolution
    knit = nil,              -- "knitrmini", "knitr", "rmarkdown" (an .Rmd)
                             -- or "knit.jl" (a .jnw); nil: see
                             -- |manuscript-knit|
    julia = { "julia" },     -- the Julia worker's command (.jnw files)
    latex = "lualatex",      -- the LaTeX engine for PDFs: "lualatex",
                             -- "pdflatex" or "xelatex"
    build_on_save = false,   -- :Manuscript build on each write
    figures = true,          -- build its standalone figures when they
                             -- changed (|manuscript-figures|)
    latexdiff = { "--math-markup=whole" }, -- latexdiff's options
    templates = nil,         -- a folder of your templates (:Manuscript new)
    identity = nil,          -- more words an anonymous submission must not
                             -- have (who you are)
    variants = {},           -- your variants (|manuscript-variants|)
    archive = nil,           -- { include = {...}, exclude = {...} }
                             -- (|manuscript-archive|)
  })
